Envelope 1.1.0: fewer dead ends between an agent draft and a human decision.

This is the public release of the operator work we have been dogfooding: a real unified inbox, a draft review experience that tells the truth, and one clear human boundary for the email you decide to send yourself.

What changed

More truthful control. Less operational drag.

Human-only Send

When you read a draft and decide to send that exact version in the dashboard, it is your send. Envelope records that action against the revision you saw and sends it as a human action. A generic approval does not create an agent bypass; edits, Hold, and agent re-queues clear the authorization.

A genuinely unified inbox

Messages now sort by real mail date across accounts, not by whichever account happened to have the highest local identifier. Pagination stays stable, slow accounts time out without freezing the page, and the dashboard tells you which account could not be reached.

Drafts that survive real work

Draft review keeps the effective sender identity, tracks replacement provider drafts after edits, renders HTML safely, and gives you Hold instead of a destructive cancel when you need more time.

MCP that speaks MCP

The stdio server now emits newline-delimited JSON-RPC, while still accepting older Content-Length input. Claude Code and Codex can use the mailbox surface without a framing workaround.

The point

Agents prepare. People decide.

Envelope is not another hosted inbox or a machine that quietly takes over correspondence. It turns the mailbox you already own into reliable infrastructure for agents, while preserving the operator’s control over real relationship actions.

The release also brings reader reply/forward actions, reversible Trash behavior, multi-account search, sender identity preservation, clearer audit records, and stronger Sent-folder proof.
