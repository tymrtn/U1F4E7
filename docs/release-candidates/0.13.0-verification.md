- `Cargo.toml` workspace version `0.12.8` → `0.13.0`; `Cargo.lock` synced
  via `cargo update --workspace` (only the four workspace members changed).
- `CHANGELOG.md` — new `[0.13.0] — 2026-07-10 (release candidate)` entry
  (v2 platform additions + outbound-send-safety fixes; notes that
  0.12.6–0.12.8 were untagged internal bumps).
- Version strings: `README.md` badge (was 0.12.5), `docs/install-linux.md`
  `VERSION=` (was 0.12.7), web brand tag in
  `crates/dashboard/web/src/routes/+layout.svelte` (was v0.12.8) → 0.13.0.
- `crates/dashboard/web/svelte.config.js` — deterministic-build fix:
  `kit.version.name` was previously unset, so SvelteKit defaulted it to
  `Date.now()`, which rewrote `version.json`, the `__sveltekit_<hash>`
  global, and every content-hashed chunk on each build — the committed
  bundle could never pass CI's bundle-drift job deterministically. It is
  now pinned to the `[workspace.package]` version parsed from the root
  `Cargo.toml` (fails the build loudly if unparseable), so the bundle only
  changes when sources or the release version change and client-side
  update detection still fires on real releases.
- SvelteKit bundle regenerated under Node v20.20.2 / npm 11.11.0 (matching
  CI's pinned Node 20), via `npx -y -p node@20 -c 'npm ci && npm run
  build'`. `version.json` now reads `{"version":"0.13.0"}` and `v0.13.0`
  is embedded in the emitted bundle. Determinism proven: two consecutive
  clean builds produced byte-identical output (SHA256 of all 58 emitted
  files compared), and a rebuild after the amend leaves
  `crates/dashboard/web/build/` clean (§4).
- `docs/schemas/envelope.agent_contract.v1.json` — **not regenerated**:
  `./target/release/envelope contract` output compared as parsed JSON
  against the committed schema → `IDENTICAL`.
- The two `docs/release-candidates/` documents.
